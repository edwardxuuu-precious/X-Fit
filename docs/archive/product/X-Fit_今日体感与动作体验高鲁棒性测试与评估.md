# X-Fit 本轮训练体验高鲁棒性测试与评估

## 1. 结论与范围

本文件是本轮功能的唯一验收矩阵，覆盖：

1. 组间计时结束弹窗与后台通知。
2. 去除重复的“计划第 N 组”。
3. RIR 改为“未记录 / 0–5”的明确选择；单边/双边改为动作级设置。
4. 新增动作到今日计划时，浅色预填上次完成记录，可直接使用或修改。
5. 动作注意事项位于动作下方，新建/修改最多 40 字，训练中最多显示两行。
6. 拍照识别器械、可做动作与训练肌群，并用肌肉图展示。
7. 动作与器械中英文、别名和 canonical ID 对齐并可搜索，历史快照不回写。
8. 动作可选择“自重（按次数）”，不要求填写重量。
9. 今日体感使用与器械识别一致的正背面肌肉图，34 个区域可点击；肌肉/部位不适以红色区域标注，关节/筋膜以红点标注。

验收必须分三层报告：

- `NDS`：不连接真机即可完成的自动化与构建。
- `RDS-C`：连接真机完成的备份、覆盖安装、启动、数据库回读与真机 XCTest。
- `RDS-M`：App 安装后可断开 Mac 的真机人工体验。

`NDS` 通过不等于真机通过；`RDS-M` 未执行时不计算综合分。

## 2. 可测试边界与发布不变量

### 2.1 公共测试缝

| 缝 | 直接验证对象 |
|---|---|
| 用户可见 UI | 文案、弹窗、状态、点击、搜索、图片、可访问性 |
| 持久化模型 | Exercise、SessionExercise、SetLog、DailyBodyCheckIn |
| 业务服务 | 休息状态机、上次设置、目录搜索、术语审核、体感标注 |
| 导入导出 | JSON/CSV 向后兼容、快照守恒、未知枚举容错 |
| 识别边界 | 本地 OCR、远端 schema、图片限制、人工确认 |
| 系统边界 | 通知、相机、签名、安装、生命周期、真实数据库 |

### 2.2 P0 发布硬门

1. 覆盖安装、导入、合并、重启前后，既有 session、snapshot、set、completed-set 数量不得减少。
2. 修改动作目录、术语或训练计划，不得回写已完成 `SessionExercise` 与 `SetLog` 历史。
3. 自重、RIR 未记录、单边/双边、体感标注必须可往返保存，不能静默改成默认值。
4. 识别结果必须先由用户确认再写入目录；低置信度或未知器械不得编造动作。
5. 远端识别不得把密钥打包进 App；失败不得留下半条动作。
6. 真机覆盖安装前必须备份 store、WAL、SHM；安装前后 `PRAGMA quick_check=ok`。

### 2.3 P1 交互不变量

1. 计时归零时前台只弹一次可操作弹窗；后台只通知一次；“+30 秒”和“开始下一组”状态一致。
2. 正常计划组只显示左侧组号；只有额外组才出现“额外组”语义。
3. RIR 默认是“未记录”，选择范围 0–5；不能用含义不明的减号按钮。
4. 单边/双边每个动作只出现一组控制，修改后应用到该动作未完成组，不改已完成组。
5. 上次设置只取最近一次已完成、非热身记录；预填后每个值都可编辑。
6. 注意事项紧邻动作，信息短且可扫读；旧数据超过 40 字仍可安全读取。
7. 中文名、英文名、器械英文名、别名任一命中同一动作；canonical 冲突不能自动合并。
8. 今日体感的正/背、左/右不可互换；34 个热区在图内且命中目标至少 44×44pt。
9. 红色区域和红点同时存在时均可见，并以面积/形状、文字与 VoiceOver 语义共同区分，不能只靠颜色。

## 4. 结果、证据和评分

### 4.1 状态

| 状态 | 定义 | 计入通过 |
|---|---|---:|
| `PASS` | 实际执行符合断言且证据存在 | 是 |
| `FAIL` | 有效断言失败，可归因到产品或数据 | 否 |
| `BLOCKED_ENV` | 设备、DDI、签名、模拟器或夹具阻塞 | 否 |
| `NOT_RUN` | 尚未执行 | 否 |
| `N/A` | 有理由确认不适用 | 不进分母 |
| `DECISION_REQUIRED` | 预期规则尚未确定 | 否 |

测试设计完成只能标 `NOT_RUN`，不能标 `PASS`。并发失败、单测重跑通过时先标 `flaky` 并保留两份证据。

### 4.2 严重级别与证据代码

- P0：数据丢失、历史回写、崩溃、重复通知/写入、识别越权。任一失败立即阻断。
- P1：主链路、状态、左右/前后、搜索、可访问性错误。必须 100% 通过。
- P2：小范围视觉、性能或边缘文案。通过率至少 95%。

| 证据 | 含义 |
|---|---|
| `UT` | XCTest 单元/属性测试与 xcresult |
| `UI-SIM` | 模拟器 UI 测试与 xcresult |
| `VIS` | 固定机型/字体/主题截图 |
| `API` | 后端 schema、multipart、错误路径测试 |
| `BUILD` | simulator 与 generic iPhoneOS 构建日志 |
| `DEV-XCT` | 连接真机 XCTest |
| `DEV-MAN` | 真机人工步骤、截图或录屏 |
| `DB` | store/WAL/SHM、quick_check、逻辑计数、指纹 |
| `EXPORT` | JSON/CSV 往返结构比较 |

### 4.3 双分数卡

| 分数卡 | 满分 | 组成 |
|---|---:|---|
| NDS | 70 | 数据/历史 18、状态机 14、搜索与识别 12、UI/可访问性 12、备份兼容 8、构建与稳定性 6 |
| RDS | 30 | 覆盖安装与数据安全 10、真实交互 8、系统能力 7、稳定性 5 |

维度得分 = 维度满分 × `PASS / 可适用项`。`FAIL`、`BLOCKED_ENV`、`NOT_RUN`、`DECISION_REQUIRED` 均不计通过。

- 发布门：NDS ≥ 67/70、RDS ≥ 28/30、P0/P1 失败为 0。
- 95–100：通过；90–94：仅限内部条件试用；低于 90：阻断。
- RDS 必测项未完成：不显示综合分，结论固定为“自动化就绪 / 真机人工待验收”。
- P0/P1 专项连续 3 轮、0 重试通过，才可标 `stable`。

## 7. 执行流程与停止条件

### A. 不连接真机

1. 固定 commit/工作树指纹、Xcode、模拟器和测试日期。
2. 先跑 T1 模型、状态机、导入导出；再跑 T2 主链路和截图。
3. 跑 API 测试、simulator build、generic iPhoneOS 无签名 build；签名与安装属于真机层，不计入 NDS。
4. P0/P1 专项连续 3 轮；不得用自动重试覆盖 flaky。
5. 填写 NDS；NDS <67 或任一 P0/P1 失败则停止，不进入真机写入。

### B. 连接真机

1. 记录 UDID、iOS、App 版本；确认设备解锁、开发者模式与 DDI 正常。
2. 先备份 store/WAL/SHM，再做 quick_check、逻辑计数和 SHA-256 指纹。
3. 只做覆盖安装，不卸载、不清容器。
4. 启动后回读版本、数据库和导出；计数减少立即停止并从备份调查。
5. 再执行真机 XCTest、相机和通知系统边界。

### C. 真机人工验收

1. App 安装后可断开 Mac，按 D-MAN-01...12 执行并录屏/截图。
2. P0 失败立即停止继续写入，保留设备现场和备份。
