## 2. 业务目标、指标与事实归属

本人以可持续记录成本完成“计划→真实录入→保存→回顾→有依据的调整”，支持有效[训练偏好](../training/用户训练偏好.md)中的身体方向；不自行设体重期限、医学判断或营养处方。新训练、漏记补录、旅行受限与恢复反馈是既有场景，不扩多用户/商业平台。

产品关注历史草稿正确、数字/中文保存可靠、动作可找到、当天与完成状态可信、结束反馈不夸大。框架减少重复解释、旧规则误用和无依据调整；内容保留术语、口径、版本与反例。

| 事实 | 真源 | Notion与调用方式 |
|---|---|---|
| 实际组、餐食照片、体重和原始时间 | App及受保护数据副本 | 必要授权摘要与定位，不上传全库/照片全集 |
| 已确认偏好与计划 | 版本化档案及App生效版本 | 展示完整版本→本人确认→追加→回读，历史不覆盖 |
| 需求、代码、测试和实际部署 | 仓库与原始证据 | 本地/设备/人工/效果分别报告 |
| 工作项、问题与协作反馈 | 原工作台 | “我的备注”“建议调整”归人所有，不由状态字段推导授权 |
| 已确认决定与经验 | 确认记录及证据 | 经验先候选，不自动全局晋升 |
| Skill方法 | 本地Skill | 保存方法和入口；个人事实留项目，不内置过期重量 |

三个原业务指标：

- **K1 核心记录任务独立完成率**：本人明确尝试中，无需额外救济且重开一致的任务数÷尝试数；训练、补录、拍照分开。缺分母为未知，不计算；样本成功不等于日常100%。
- **K2 同任务记录负担**：录入/纠错/切换的用时、纠错与补救次数和本人手感，不计组间休息。没有可靠旧版基线不声称提速比例；App侧采集不是物理触键P95。
- **K3 可追溯复盘闭环**：关联实际、恢复反馈、有效偏好、理由、完整提案及必要确认/回读。维持或减量也可构成有依据的决定，长期身体收益另观察。

硬护栏：实际记录/照片不丢失、重复新增零、未知不补零、人工内容不覆盖、未授权写入零；临时规则到期检查、历史草稿不是负重建议、缺关键输入不编造进阶。低负担记录是否提高长期效果仍为待真实使用验证的假设，不拿页面/测试数量当收益。

## 4. 原有限迭代流程

| 阶段 | 动作 | 出口 |
|---|---|---|
| S0 目标合同 | 确定本人任务、目标、指标、非目标与授权 | 可检查的确认合同 |
| S1 事实检查 | 核当前版本、权属、日期、单位、缺项和冲突 | 当前观察与旧证据区分 |
| S2 问题与假设 | 描述观察及至少一个会改变决定的替代解释 | 可检验假设、最小反证 |
| S3 有限方案 | 比较现状/最小改进/较大选项，写理由、tradeoff和停止条件 | 有理由的有限包；具体计划/写入仍另确认 |
| S4 执行 | 在已有授权内实现；共享状态/设备/Notion串行 | 实现与需求可映射，不扩大范围 |
| S5 分层验证 | 本地、实际端、本人和效果分别留证 | PASS/FAIL/BLOCKED_ENV/BLOCKED_HUMAN/NOT_RUN，不相互替代 |
| S6 观察复盘 | 比较预期与实际，保留/修改/停止 | 可恢复缺步骤；经验候选，不自动开下一轮 |

每条产品/框架/内容线最多一个主要在制包；只有适用的委派授权存在时才给worker独立局部任务，根任务合并、控制共享写入与最终结论。任务状态仍pending/in_progress/blocked/done，done不等于手机/人体效果。依问题、证据与依赖触发，不作日期工期承诺。

同一阻塞反复出现时在原节点拆最小解除子树，列原因状态、负责方、出口和恢复条件；无新证据不盲重试、不以新报告替代结果。阻塞只停止依赖分支；无独立授权工作就结束并保留恢复条件。宿主Goal只在实际存在时按其规则处理，不伪造active/paused/complete。
