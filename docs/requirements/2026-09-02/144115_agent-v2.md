## 目标

- 将工具页从工具矩阵升级为对话优先的 Agent 工作台，同时保留快速人工入口。
- App 仅调用 X-Fit HTTPS 代理，不接收、保存、记录或发送 DeepSeek 开发者 Key。
- DeepSeek 只负责把自然语言转换为回复、澄清问题或白名单工具提案；本地命令模块继续负责验证与写入。
- 远程不可用、超时或协议无效时，自动尝试 V1 本地解析；明确展示当前来自“DeepSeek”还是“本地理解”。
- 写操作继续展示确认卡；读操作可直接返回结果；取消确认不产生本地写入。
- 服务端只接收当前对话的有限消息和最小今日摘要，不上传完整训练记录或数据库。

## 非目标与边界

- 不把 DeepSeek Key、代理服务 Key或任何长期 Provider Secret 写入源码、Info.plist、UserDefaults、SwiftData 或 iPhone Keychain。
- 不部署或写入真实外部服务；手机端仅按用户追加授权执行覆盖安装，不卸载或清容器。
- 不允许 DeepSeek 直接访问 SwiftData，不允许模型返回任意方法名、SQL、脚本、URL 或自由参数后直接执行。
- 不提供医疗诊断、伤病治疗、营养处方或自动训练决策；模型回复必须限制在记录、查询和澄清工具意图。
- 不上传完整对话历史；最多发送最近有限轮次，限制单条长度并移除空白内容。
- 不改变第五个工具 Tab、首页不放工具、喝水/跳绳/久坐/体重领域语义和备份模型。
- 代理线上配置与 DeepSeek 真实费用请求仍属于后续验证层；真机覆盖安装已完成，真机 XCTest 与真人体验仍未执行。

## 当前事实

- V1 已存在 `WellnessToolCommand`、`WellnessToolService` 与 `LocalWellnessAgent`；写命令统一通过本地 SwiftData seam。
- V1 UI 为折叠卡片 + 2×2 工具矩阵，视觉上仍更像表单页，未形成连续对话和来源状态。
- App 已有 provider-agnostic HTTPS 代理模式：`ExerciseTerminologyAPIClient` 不发送 Authorization 或 apiKey，且已有测试锁定该边界。
- 仓库包含 `EquipmentRecognitionBackend` Fastify 服务，可新增独立 `/v1/wellness/agent` 路由，但当前没有生产部署配置或已授权的外部写入目标。
- `FitnessApp/Info.plist` 只配置现有器械识别 endpoint；需新增非秘密的 Wellness Agent 代理 endpoint。
- 当前工作树存在大量其他已确认需求的未提交修改；实现需避开回退、格式化或覆盖共享改动。

### 已确认测试 seam

- 代理协议 seam：向 `/v1/wellness/agent` 提交受限请求，返回固定 schema、回复和白名单提案；Provider Key 只从服务端环境读取。
- App 远程 adapter seam：HTTPS 请求不含 DeepSeek Key，严格校验 schema、工具名、数值范围和响应；不在此 seam 写 SwiftData。
- 混合 Agent seam：远程成功返回来源为 DeepSeek；网络/5xx/无效协议时调用本地 fallback；两条路径只产生提案或回复。
- UI seam：Agent 输入成为首屏主操作，展示对话、理解来源、思考状态和快捷指令；写提案仍进入确认卡。
