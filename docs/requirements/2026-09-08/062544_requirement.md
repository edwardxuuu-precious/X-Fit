## 用户原始需求

用户不接受全身混合训练，希望每次聚焦 1–2 个肌群并获得充分刺激；大肌群作为健康和力量基础重点安排，肩膀与手臂允许更多组数，并增加有氧。用户要求把偏好和具体编排记录下来，今后每次编排必须读取。本轮确认正式替代旧三日全身规则，采用四日分化、每周两次跳绳加一次 Zone 2，并同时保存到 App 与项目档案。

## 目标

- 将已确认训练偏好保存为带生效日期、原因和版本号的 App 数据，并建立项目真源文档。
- 将当前周计划保存为关联偏好版本的编排快照：周二胸＋三头、周四背＋二头、周六腿＋核心、周日肩＋手臂。
- 训练推荐调用显式传入当前偏好；肩臂加量、大肌群优先、低能量晨练和不跑步规则可见。
- 每周两次跳绳与一次 Zone 2 进入编排；力量日程仍由用户预览后手动导入。
- JSON 备份完整保存并恢复偏好和编排版本，旧备份继续可读。

## 非目标与边界

- 不自动创建日程、不把计划当完成记录、不覆盖同日现有训练，也不修改既有训练 UUID、已完成组或历史计划。
- 不把训练偏好推导为高蛋白、肉类份量或医学结论；肌酐、eGFR、总蛋白和肉量仍待医生/营养师确认。
- 本轮不覆盖安装手机、不清空 App 数据、不提交、打 tag 或发布。
- 训练重量使用同动作历史、目标次数和 RIR 动态建议，不在缺少可靠历史重量时编造固定公斤数。

## 变更前基线

- 原减脂目录是周一/三/五三日全身 A/B/C、16 个动作、每动作 2 组；用户已明确废弃该训练内容。
- 训练推荐此前只读取 `TrainingGoalMode`，没有可持久化的个人训练偏好，也未记录推荐所用偏好版本。
- 现有日程导入已有预览、防重、冲突拒绝/跳过及独立模板快照；这些规则继续复用。
- 变更前 JSON 备份为 schema 13，减脂备份尚未包含训练偏好和编排版本；本轮实现已升级为 schema 14。
