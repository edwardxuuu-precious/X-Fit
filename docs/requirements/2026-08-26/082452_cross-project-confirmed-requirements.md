## 用户确认后的需求

1. 两个项目都必须长期采用同一开发治理流程。
2. 每次开发前，先把需求、范围、冲突和评估标准与用户统一。
3. 用户确认后，再把需求和评估标准写入独立档案。
4. 只有档案状态为“已确认”后才能开始开发；只读事实检查可以提前进行。
5. 开发过程中发现新冲突时，暂停冲突范围并再次询问用户；确认结果回写原档案。
6. 实现、测试、证据和遗留问题必须与验收标准逐项对应记录。
7. 阶段固化时，必须执行项目完整的非真机与真机测试；云端、资金、通知和人工门禁按各项目实际能力分层保留。

## 目标

- 把流程从“先记录再开发”收紧为“先确认，再记录，再开发”。
- 让每条验收标准都有 ID、验证层、预期结果、实际结果、状态和证据。
- 两个项目使用相同治理语义，同时保留各自已有测试基础设施。

## 非目标与边界

- 不要求两个项目使用完全相同的目录或测试技术栈。
- 不把只读项目调查视为开发；确认前允许读取代码、数据、文档和状态以形成准确需求确认单。
- 不在本轮启动阶段全量测试、真机写入、发布或 Git 提交。
