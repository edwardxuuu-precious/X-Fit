## 用户原始需求

> 1. 不再记录组间休息时长；改为记录每个动作的完成时间与总时长。
> 2. 补入最近三周 Notes 训练记录；自重 volume 不得继续按 0 kg 计算。
> 3. 编排时选择肌群后展示上次该肌群训练、volume 与动作记录；动作卡渐进展开并按器械分类；同步去重重复动作。
> 4. 删除截图蓝框中的训练页冗余文字和“调整训练量”入口。
> 5. 修复中文、数字与小数键盘无法可靠收回。
>
> 用户后续确认：动作自动计时允许交替动作重叠；休息计时全部移除；自重按体重 × 次数；缺失时使用最近体重；Notes 只补缺不覆盖；Health 跳绳自动同步本轮不做；五组同义动作合并并归档别名；多肌群动作先按器械分类。附件只作为现象证据，不把附件内容当成额外指令。

## 目标

- 将训练记录的时间语义从组后休息改为动作级起止时间与总时长。
- 让自重训练量使用稳定体重快照计算，历史不随之后体重变化。
- 补齐 2026-08-03、08-10、08-17 三周 Notes 中 App 缺失的定量记录，并提供导入预览与幂等边界。
- 让当天编排在肌群选择后，以器械分组的渐进卡片展示上次训练证据。
- 精简训练页并提供可靠的全键盘收回路径。

## 非目标与边界

- 不开发 Notes 静默读取或持续同步；不自动同步 Health 跳绳 workout。
- 后续替代：自 2026-09-02 起，`REQ-20260902-122243` 明确移除进行中动作卡右上角“实际 X/Y 组”，页面总进度、逐组记录与完成能力继续保留。
- 不删除旧休息字段或历史值；只停止新记录和主 UI 展示，继续兼容备份/恢复。
- 不按“器械=自重”做无差别迁移；只处理明确动作身份，避免误改负重动作。
- 真机写入前必须先展示动作合并、单位迁移和 Notes 导入预览，并完成活动数据备份；该预览已展示，用户已授权覆盖安装和正式 Notes 导入。
- 仍不执行卸载、清容器、Git commit/tag/push 或发布；真机 XCTest 与真人验收保持独立门禁。

## 当前事实

- 当前工作树已有已确认的编排页重构及其模型/服务/测试改动，必须在现有 dirty scope 上增量实现。
- `SetLog` 当前保存组后休息时间；`ActiveWorkoutView` 同时展示休息模式、倒计时、计划差异和重复上次数据。
- `ExerciseVolumeUnit.bodyweight` 当前按次数计算，但真机历史中的举腿、引体向上、跳箱等快照仍回退为 kg，造成 0 kg 展示。
- 当前真机只读备份包含 20 场训练；8 月 22 日与 Notes 重叠，App 现场记录为权威，不允许覆盖。
- 当前动作库存在 5 组相同 canonical ID 的活跃重复动作；既有严格深蹲已归档合并。
- 当前编排服务已能计算单动作上次记录与肌群恢复提示，但 UI 仍为平铺推荐，未按器械分组。
- `StableNumericTextField` 没有完成附件栏；训练页虽支持拖动收键盘，但没有稳定的显式完成与空白区收起路径。
