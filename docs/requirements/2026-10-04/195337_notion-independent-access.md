## 非目标与边界

- 不修改或注销共享插件／全局 MCP 连接，不使用其他项目的令牌，不读取无关 Keychain 项。
- 不移库、不复制旧档案、不公开分享；不覆盖历史快照、“我的备注”或“建议调整”。
- 不改变 `xfit-project-loop.py`、`xfit-training-archive.py` 的离线合同；联网读写另建入口。
- 不安装手机、不写手机实际数据、不编排未经展示确认的新训练，不部署服务器、后台调度或提交 Git。
- 内部连接 API 不能直接建立个人根级私有页；新工作台需要明确的私有父页及授权，未取得前不选其他父页。

## 研究、方法与取舍

- 问题：在不影响其他项目、不复制原库的前提下，能否独立读取和受控同步？用途是本轮实现；结论上限为官方支持＋本地行为验证，不等于上线效果。领域为技术接口／隐私，采用标准证据与高风险凭证护栏。
- 单一权威证据链：Notion 官方；2026-10-04 实际阅读内部连接权限、User bot 字段、数据库／数据源、Markdown、Create page 与查询结果上限说明；当前版本 `2026-03-11`。
- 强反证：内部连接不能建个人根级私有页；API 可读不证明未共享。处理：保留父页／隐私人工门，不偷偷改用 PAT 或复用某条旧训练记录当工作台父页。
- decision：先稳定原档案通道；不新增 npm／MCP 运行时依赖，使用现有 Python3 和官方 HTTPS API。tradeoff：需维护小型适配器、首次人工授权；换取独立凭证、固定范围和明确失败。
- 未来方向：确切私有父页后接三库蓝图；之后才讨论独立 MCP 外壳、增量读取或调度。本期不实现无界自动写入。
