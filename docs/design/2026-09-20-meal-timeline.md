# 餐食照片时间线页面设计

- 需求：`../requirements/2026-09-20/174104_meal-photo-travel-week.md`
- 用户已确认：AteMate 时间线方向、X-Fit 深色视觉、无服务器离线保存、整周一次确认后回写。
- 设计先于实现；本页不代表真人体验通过。

## 首页：让记录先发生

顶部保留 X-FIT / NUTRITION、今日饮食、日期选择。首屏显示当天真实餐食时间线，卡片按发生时间排列，含照片、当地时间、餐次、原记录摘要与“待评估 / 营养未完整 / 已确认估算”状态；文字历史使用文字卡，不用菜式示意图冒充实拍。空日显示“拍一张，先记下来”，不把空白解释为没吃。

底部固定“拍照记餐”主按钮，至少 44 点触控区域；不遮挡滚动内容。周回顾为次入口。原有计划餐、备餐、饮水、手动记录、全部记录与餐单入口保留在时间线之后；计划示意与真实照片分区，不混淆。

## 拍摄与保存：照片即可成餐

点击主按钮直接请求并打开系统相机。系统相机提供重拍/使用照片；返回后进入确认页，横向预览已选照片，可移除尚未保存的照片、继续拍摄或从相册添加。日期时间、餐次自动带入且可改过去日期；备注可留空，不要求菜名/份量/热量。

保存主按钮固定底部；没有照片时不能保存，取消不产生餐食。相机不可用/被拒绝时显示原因、相册替代与设置入口，界面仍可关闭。选择过程仅在内存中；确认保存后一次经照片服务持久化。追加照片由同一确认页处理，不新建第二餐、不重写原文。

## 详情：原始资料与估算分开

原照片支持横向查看，展示原餐次、当地日期时间、原名称和原备注；“继续拍照”追加到当前餐。已知本人热量及来源独立显示，未知宏量明确写“未知”。Codex 评估单独分区显示菜品、份量、热量区间、疑问及来源；不能把估算包装成实测。既有手动编辑入口保留。

## 周回顾：可解释的离线交接

以选择日所在周为范围，显示记录餐数、照片餐数、待评估数与七天分布。无记录的日子显示“未记录”，不产生 0 kcal。显示连接 Mac 后由 Codex 读取、整周确认后回写的说明；提供周包导出与评估 JSON 导入预览。导入先展示整周摘要和不确定项，用户一次确认再调用服务回写；源变化、无效包或重复应用必须显示真实结果。

## 视觉与可访问性

沿用背景、暖白标题、柠檬黄主操作和现有圆角；照片占主要视觉面积，状态用文字而非只靠颜色。大字号布局纵向展开，按钮不挤压。每个操作提供中文 accessibilityIdentifier；相机不可用、取消、原文可见、周回顾与大字号固定按钮在公开 UI 边界测试。

## 验证边界

- UI 自动化仅替代模拟器无硬件时的相机输入边界，不伪装真实拍摄验证。
- 真机相机授权/重拍/成片质量、相册权限与连接 Mac 流程仍需设备/真人验证。
- 原照片与周评估保存在核心服务；页面不直接改底层数据库，不调用网络 AI。

## 实现约束与交接

- 保存前把相机/相册输入规范化为最长边不超过 2048 像素的 JPEG，去除相册位置等附带元数据；规范化后保存的字节作为不可变的原始餐食照片。每餐最多 12 张，达到上限后禁用继续添加。
- 首页和周回顾按设备当前日历选日期；已有记录按各自保存的当地日期归档。旧餐单继续使用原上海日历，由选中的年月日转换，不用澳洲午夜时刻推算旧餐单。
- 无签名模拟器无法使用生产 App Group，UI 测试照片必须位于独立的测试存储；真机生产目录仍保持 App Group，不能用测试回退冒充真机可用。
- 实现位于 `NutritionHomeView` 与独立的 `MealPhotoComposer`、`MealPhotoDetailView`、`MealWeekReviewView`；可追溯估算由 `MealAssessmentCard` 单独展示。
- 自动化测试位于 `MealPhotoUITests`。真实相机与用户体验依然是独立的真机验收项。
